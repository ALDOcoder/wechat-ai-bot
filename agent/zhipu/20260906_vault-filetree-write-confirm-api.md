## 2. 安全模型总览

```
                     ┌──────────── 无密钥（默认） ────────────┐
   聊天面（不上锁） │  /api/reply、/api/health、会话接口照常  │
                     └────────────────────────────────────────┘
   管理面（上锁）   │  文件树 / 规则 / 检索调试 / 索引数 /     │  ← 全部 401，
                     │  解锁目录 / 手动建文 / AI草稿管理        │     前端只显示锁屏
                     └────────────────────────────────────────┘
                            ▲ 输入密钥
                     POST /api/vault/session → token（内存，30 分钟）
                            │ 之后所有管理请求带 X-Vault-Token
                     ┌────────────────────────────────────────┐
                     │ 文件树可见 · 规则可管 · 可建笔记         │
                     │ 40-Life 仍显示为 🔒 节点（需再点解锁）   │
                     └────────────────────────────────────────┘
```

两层语义，**一把密钥**：

1. **管理面门禁**（新增）：看不到任何路径/规则 → 密钥换 token 后可见
2. **保护目录**（延续）：进入管理面后，`40-Life` 仍是折叠的 🔒 节点，需显式点击「加入索引」才会索引（此时已持有效 token，无需再输密钥）

> 已知风险消除：原方案「文件树 = 全库标题对局域网暴露」不再成立——树本身就在门禁后面。

## 3. 接口契约

### 3.1 POST /api/vault/session —— 密钥换令牌

```json
{ "key": "用户输入的密钥" }
```

成功 `200`：

```json
{ "token": "8c1f...随机串", "remainingSeconds": 1800 }
```

失败：

| 状态码 | 场景 | 响应体（纯文本，前端直接展示） |
| --- | --- | --- |
| `401` | 密钥错误 | `密钥不正确` |
| `429` | 失败过多（防爆破：按 IP 连错 5 次 → 锁 10 分钟） | `尝试次数过多，请 10 分钟后再试` |

**令牌约定**：

- 后端内存暂存（随机串 → 过期时间），**重启即全部失效**（天然安全兜底）
- 有效期建议 **30 分钟**，建议滑动续期（每次成功的管理请求刷新过期时间）或固定时长，后端定
- 前端存 `sessionStorage`（不持久化，关标签页即失效），后续管理请求带请求头 `X-Vault-Token: <token>`
- 可选：`POST /api/vault/session/close` 主动失效（前端「退出管理」按钮用）

**门禁范围**：`/api/vault/**` 与 `/api/rag/**` 下所有接口（含既有的 `/api/rag/status`、`/api/rag/patterns*`、`/api/rag/search`）一律要求有效 `X-Vault-Token`，否则 `401`（纯文本 `需要密钥`）。`/api/reply`、`/api/health`、`/api/sessions*`、`/api/conversations*` 不受影响。

> 特别强调 `/api/rag/search`：它直接返回笔记内容，是最大的泄露面，必须门禁。

### 3.2 GET /api/vault/tree —— 文件树（P1，需令牌）

```
GET /api/vault/tree          （请求头 X-Vault-Token: <token>）
```

成功 `200`：

```jsonc
{
  "root": "C:\\Users\\ChelseaFC\\Desktop\\wo\\webflow",
  "nodes": [
    { "path": "10-Daily/2026-09-05.md", "status": "indexed" },
    { "path": "30-Old/tmp.md", "status": "excluded", "rule": "30-Old" },
    { "path": "40-Life/", "status": "protected", "fileCount": 3 }
  ]
}
```

- 扁平文件路径列表（前端自行组树）；**不含安全基线（`.mimocode` / `node_modules` / `.obsidian`）下任何路径，任何接口都不返回它们**
- `status`：
  - `indexed` 可检索
  - `excluded` 被普通排除规则挡住，`rule` 带来源规则
  - `protected` 受保护目录节点（`path` 以 `/` 结尾 + `fileCount`），**未加入索引前绝不返回其子文件路径**
- 只回路径 + 状态 + 计数，不返回内容

### 3.3 保护目录 加入 / 移出 索引（P1，需令牌）

```
POST /api/vault/protect/add     { "path": "40-Life" }
→ 200 { "indexed": true, "files": 27, "chunks": 91 }    // 重建后最新索引数

POST /api/vault/protect/remove  { "path": "40-Life" }
→ 200 { "indexed": false, "files": 24, "chunks": 79 }   // 幂等
```

- 持久化（建议 DB 表如 `rag_unlock_path`，**重启不丢**——这是索引成员资格，区别于上一版的内存 TTL）
- `path` 不是已配置的保护目录 → `400 不是受保护的目录`
- 保护目录清单：起步固定 `40-Life`，建议 yml 可追加（如 `rag.protected-dirs`）

### 3.4 POST /api/vault/note —— 手动新建笔记（P2，需令牌）

```json
{ "path": "10-Daily/2026-09-07.md", "content": "# 标题\n正文..." }
```

成功 `200`：`{ "path": "...", "files": 25, "chunks": 83 }`（落盘 + 进索引，若目录未被排除/保护）。

| 状态码 | 场景 | 文案 |
| --- | --- | --- |
| `400` | 路径非法（越界 / 非 .md / 落在安全基线或未加入索引的保护目录内） | `路径不合法：xxx` |
| `409` | 文件已存在 | `文件已存在：10-Daily/2026-09-07.md`（MVP 不做覆盖） |

后端必须做路径规范化与 `..` 越界校验；前端校验仅为体验。

### 3.5 AI 写入确认 —— 两阶段落盘（P2）

#### ReplyResponse 扩展

```jsonc
{
  "reply": "已生成笔记草稿，确认后将写入 90-Agent/xxx.md",
  "ragUsed": false, "provider": "zhipu",
  "pendingNotes": [ { "id": "pn_8f3a", "path": "90-Agent/xxx.md", "content": "# ..." } ]
}
```

- Agent 调 `writeNote` 时**不落盘**，生成 pending 条目（内存暂存，TTL 建议 10 分钟）随回复返回
- 数组契约预留多条，MVP 单次回复最多一条
- **确认/拒绝接口不要求令牌**（路径是 AI 生成的 agent 输出目录、内容来自用户当前对话上下文；是否收紧见第 7 节待确认项 5）

```
POST /api/vault/note/confirm   { "pendingId": "pn_8f3a" }
→ 200 { "path": "...", "files": 26, "chunks": 85 }     // 此时才落盘 + 进索引
→ 404 `确认已过期，请让 AI 重新生成`

POST /api/vault/note/reject    { "pendingId": "pn_8f3a" }
→ 200 { "rejected": true }      // 幂等
```

#### 前端消费

聊天流中带 `pendingNotes` 的回复渲染为确认卡片（路径 + 内容预览 + 确认写入 / 拒绝）；确认后追加系统消息「✅ 已写入 …」并刷新文件树。

## 5. 安全与边界

1. 一把密钥（环境变量 `RAG_VAULT_KEY`，常量时间比较，禁止进提交的配置文件）管整个管理面；保护目录的加入/移出在持令牌后无需二次输密钥
2. 令牌仅内存、重启全失效、可主动关闭；密钥只在 session 接口出现一次，不随业务请求重复传输
3. 安全基线任何接口不可解锁、不可见——不可协商底线
4. 路径类接口统一做规范化与 `..` 越界校验
5. 隐私边界声明延续：排除/锁定只作用于检索层，历史消息与对话记忆不受影响
6. 防爆破细节：
   - 客户端 IP 获取复用现有 `resolveClientIp()`（Vite 代理已开 `xfwd`，`X-Forwarded-For` 携带真实 IP）
   - **防伪造规则（必须）**：仅当请求来自可信代理（`remoteAddr` 为 127.0.0.1）时才采信 `X-Forwarded-For`；直连 8080 的请求一律用 `remoteAddr`，忽略客户端自带的 XFF——否则攻击者可伪造头换 IP 绕开锁定
   - **全局兜底（建议）**：除按 IP 计数外，加一个全局失败计数（如 5 分钟内全服失败 ≥ 50 次 → 全局锁 10 分钟），防止伪造海量假 IP 分布式枚举
   - 失败计数存内存即可，重启清零

**实现补充（前端需要知道的与 v2 文档的差异点）**：

1. **40-Life 已从 yml 排除基线挪到 `obsidian.protected-dirs`**——基线（.mimocode / node_modules / .obsidian）与保护目录是两层语义：基线永不可解锁、任何接口不可见；保护目录可经 protect/add|remove 切换并持久化。原基线若保留 40-Life 会导致"加入索引"永远无效（并集下基线优先），故必须迁移。
2. 文件树中 `_index.md` / `*moc.md` 导航文件状态为 `excluded`，`rule` 返回 `"导航文件(_index/moc)"`。
3. 保护目录即使库内不存在（如当前 webflow 库暂无 40-Life 目录），文件树仍返回其折叠节点（fileCount=0），protect/add/remove 照常可用（幂等）。
4. `POST /api/vault/note` 落在**字典排除目录**内：允许写入（200），但不进检索索引（files/chunks 不会包含它）——与 3.4 节"若目录未被排除/保护"的描述一致。
5. 全局防爆破兜底已实现（5 分钟内全服失败 ≥50 次 → 全局锁 10 分钟）；XFF 仅在本机可信代理（remoteAddr 为回环）时采信。
6. 草稿确认的重复调用：第一次 confirm 成功后草稿即被消费，再次 confirm → 404「确认已过期」——请按一次性操作处理。
