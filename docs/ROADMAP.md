# 项目路线图 · 方向指引

> 定位一句话：**个人 AI 助手——微信只是入口，核心是“让 AI 基于我的真实数据工作”。**
> 本文档回答：这项目是什么、对主人有什么价值、往哪走、每步怎么验收。

---

## 1. 为什么做这个项目（价值）

1. **面试作品集**（最确定的价值）：Spring Boot 3 + Spring AI + 多轮记忆 + 知识库检索 + Python
   UI 自动化，是一份能讲、能演示的 AI 应用项目，与个人作品（fu-记账系统、雅集聊天室）串成
   “全栈 + AI”的故事线。
2. **个人知识助手**（长期用处）：面试资料、项目文档、学习笔记存在 Obsidian，
   通过微信随时提问，AI 基于**自己的笔记**回答，而不是通用大模型瞎编。
3. **技术成长**：Spring AI、RAG、工具调用、多线程、网络/风控、Git 协作，都是求职加分技能。

## 2. 核心原则

- **Java 端积累 AI 能力**（记忆、检索、工具调用）——这是长期资产；
- **微信端只是演示入口**——不追求完美稳定（微信封控/版本变更不可控，随时可能失效）；
- **本地数据优先**：笔记、聊天记录都在本地，AI 能力可离线检索、在线问答；
- **隐私与风控**：个人微信自动化违反微信 ToS，只跑测试小号；笔记内容会发给远端大模型，
  敏感内容（如私人聊天）默认不索引。

## 5. 阶段 2（当前）详细说明

- **目标**：把 Obsidian 库变成机器人的“参考书”，提问时检索相关笔记拼进 Prompt。
- **范围**：默认索引 10-Projects / 20-Interviews / 30-Knowledge / 50-Resources/Templates；
  排除 `.mimocode`、`node_modules`、`.obsidian`、`40-Life`（私人聊天默认不进知识库）。
- **技术**：启动时扫描 Markdown → 去 frontmatter → 按标题/段落切块 → 关键词（BM25 风格）评分
  → 命中 top-k 拼进 Prompt。
- **接口**：`GET /api/rag/status`（索引状态）、`POST /api/rag/refresh`（重建索引）、
  `GET /api/rag/search?q=...`（调试检索）。
- **配置**：`obsidian.vault-path`（或环境变量 `OBSIDIAN_VAULT_PATH`）、`top-k`、`max-chunk-chars`、
  `exclude-patterns`。

## 6. 已知风险与边界（诚实清单）

- **微信风控**：UI 自动化违反微信 ToS，账号可能被封——只跑测试小号，别用主号；
- **版本脆弱**：微信升级可能让 wxauto 失效，微信端按“可演示”标准维护即可；
- **RAG 局限**：关键词检索依赖词面命中，换种说法可能搜不到；后续可升级向量检索；
- **隐私**：索引的笔记内容会随提问发送给 DeepSeek，私人聊天默认排除；
- **记忆边界**：多轮记忆在内存中，重启清空；聊天归档落盘后才算真正“记得”。

## 7. 决策备忘（给未来的自己）

- 这个项目是“长期技术项目”，不是“微信机器人商业产品”——别被微信端折腾带偏重心；
- 每个新功能先问：**它让机器人“更有用”还是只是“更酷”？** 优先做前者；
- 面试前，把阶段 1/2 的成果整理成一段 3 分钟能讲完的项目故事。
